8. KNOWN LIMITATIONS & PROTOTYPE BOUNDARIES
================================================================================

1. Client-Side State Persistence:
   - All state modifications (simulated credential updates, shift assignments, and activity
     log entries) exist in client-side memory. Refreshing the browser resets the data to
     the initial mock state. A dedicated "Reset Demo Records" button is provided for manual resets.

2. Fictional Data & No External API Integration:
   - As per prototype requirements, the application does not query real external certificate
     issuers (American Heart Association, State Nursing Councils) or integrate with hospital
     payroll/HRIS databases. Simulated edits are explicitly marked with disclaimers.

3. Role Policy Scope:
   - Mandatory credential rules are fully modeled for the Nurse role (BLS + State Nursing
     Council). Roles such as General Physician and Pharmacist intentionally display an
     unconfigured role warning rather than inventing fictional requirements.

4. Audit Trail Implementation:
   - The Validation Activity log is an educational simulation illustrating operational
     auditing. It is not an immutable, tamper-proof, blockchain-backed enterprise compliance system.

5. Date Evaluation Scope:
   - Credential validity is evaluated relative to the fixed system demo date (18 Oct 2026).
     If a future shift is scheduled (e.g. 20 Oct 2026), the engine currently evaluates whether
     the credential is valid as of the demo date per case-study specifications. In enterprise
     production, a secondary check against the future shift date would also be enforced.
